Public API

The names below are declared public in src/TileInfer.jl. Only the backend types are exported, so qualify the rest (TileInfer.generate) or import them (using TileInfer: generate, load_model). See Getting started for how they fit together, and Internals for everything else.

Conventions shared by every function here: arrays are column-major with PyTorch's shapes reversed (hidden states (hidden, tokens), linear weights (in, out) applied as y = Wᵀx), token ids are 0-based as in the Hugging Face vocabularies, and the element type T of a model (BFloat16 by default) is a type parameter.

TileInfer.TileInfer — Module
TileInfer

A single-GPU LLM inference engine for Llama-style models (Llama 3, Mistral, Qwen3, Apertus), with its hot kernels written in cuTile.jl. Built to learn how inference engines work, not for production use.

Start with pull, load_model, load_tokenizer and generate or ChatSession; the tileinfer command line (cli) wraps the same calls.

TileInfer.forward! — Function
forward!(model, cache, seq, ids; all_logits = false) -> CuMatrix{Float32}

Run the 0-based token ids through the model at the positions following those of seq, storing their keys and values in cache and appending them to seq. Returns the logits (vocab, n) of every token if all_logits, otherwise (vocab, 1) of the last token. Runs eagerly with buffers allocated for this step; ModelRunner reuses them.

source
forward!(runner, seq, ids) -> CuMatrix{Float32}

forward! through runner: the logits (vocab, 1) of the last token. For short steps they live in the step's static buffers and are overwritten by the next step of the same length, so read them before running another step.

Port of Qwen3's template without tool calling. Two details matter:

  • assistant turns before the last user message drop their <think>…</think> reasoning, so earlier reasoning does not use up context;

Port of Apertus 1.5's template (chat_template.jinja) for text messages without tools. A system message may only come first; without one, the template's default is used. The developer turn says whether the model may deliberate (think between <|inner_prefix|> and <|inner_suffix|>). Consecutive assistant messages form one turn. Earlier reasoning is kept.

KV cache

TileInfer.PagedKVCache — Type
PagedKVCache{T}(config, num_pages; page_size = 64, quantize = nothing, key_smoothing = nothing)

Key/value page pools for every layer and the allocator for their pages, for a model whose activations are T. The pools hold T, or with quantize = :int8 Int8 values with one Float32 scale per cached vector (Int8Pages): about half the memory, and half the bytes decode attention reads. key_smoothing holds each layer's smoothing of the keys of an INT8 cache (see key_smoothing), or nothing for none.

TileInfer.generate! — Function
generate!(runner, seq, ids; max_new_tokens = 256, sampling = SamplingParams(),
          stop_ids = model.config.eos_token_ids, rng = Random.default_rng(),
          on_token = nothing, pipeline = true, speculative = nothing,
          spec_stats = SpecStats()) -> Vector{Int}
generate!(model, cache, seq, ids; kwargs...)

Continue seq with the 0-based token ids and generate up to max_new_tokens tokens. Returns the new token ids, without the stop token. on_token(id) is called after each new token, for streaming. Afterwards seq holds ids and every generated token except the last one, which was sampled but never run through the model.

The tokens are a function of the logits and one seed drawn from rng (see sample_host), however they are sampled: on the device when the sampling is on_device, pipelined (generate_pipelined!) on a runner with CUDA graphs unless pipeline = false; otherwise on the host, step by step.

With a proposer as speculative (such as NgramProposer), decoding checks its drafts several tokens per step (generate_speculative!) and counts them in spec_stats; the sampling must be on_device.

source

generation_defaults(model_dir, config) -> (SamplingParams, stop_ids)

Speculative decoding

TileInfer.NgramProposer — Type
NgramProposer(; k = 4, max_ngram = 3, min_ngram = 1)

Proposes up to k tokens by prompt lookup: find the latest earlier occurrence of the last n tokens (n from max_ngram down to min_ngram) and propose the tokens that followed it.

source
TileInfer.DraftProposer — Type
DraftProposer(draft_model; k = 4, sample = false, max_tokens = max_length(draft_model),
              graphs = supports_graphs(draft_model.backend))

Proposes the next k tokens that draft_model decodes greedily, on a KV cache of its own for up to max_tokens positions; or, with sample and a target that samples, that it samples with the target's sampling parameters, verified by the p/q rule. The draft model must share the target's vocabulary.

source
TileInfer.DFlashProposer — Type
DFlashProposer(drafter; k = drafter.block_size - 1, sample = false, max_tokens = max_length(drafter),
               graphs = supports_graphs(drafter.backend))

Proposes the first k of the block_size - 1 tokens that the DFlash drafter (see load_dflash) drafts in one pass, on a KV cache of its own for up to max_tokens positions: the argmax at each block position, or, when sample and the target samples, a sample with the target's parameters (each position independently: the block's positions do not see each other's drafts, so q of draft j is the drafter's distribution at position j). Reads the hidden states of the target's latest step, which generation enables on the target's runner.

Backends and ops

Every op has a RefBackend method (CUDA.jl broadcasts and cuBLAS) and a TileBackend method (cuTile kernels), and an in-place form that the model's forward step calls on preallocated buffers.

TileInfer.Backend — Type
Backend

Selects the implementation of every op by dispatch: RefBackend (CUDA.jl broadcasts and cuBLAS, the ground truth) or TileBackend (cuTile kernels). A model holds its backend, so load_model(…; backend = TileBackend()) runs it on the cuTile kernels.

TileInfer.RefBackend — Type

Reference ops: CUDA.jl broadcasts and cuBLAS. Ground truth for correctness tests.

TileInfer.XIELU — Type
XIELU{T}

The learned scalars of a layer's xIELU activation (Apertus, arXiv:2411.13010), in the form transformers applies them, each rounded to T as there: x > 0 ? αp x² + β x : (expm1(min(x, ε)) - x) αn + β x.

TileInfer.store_kv! — Function
store_kv!(backend, k_pages, v_pages, k, v, slots)

Write the keys and values (head_dim, kv_heads, n) of n tokens into the page pools (head_dim, page_size, kv_heads, num_pages) at the 1-based cache slots (a device vector, see slots): slot s is offset (s - 1) % page_size of page (s - 1) ÷ page_size + 1.

source
TileInfer.attention — Function
attention(backend, q, k_pages, v_pages, block_table, positions, scale; causal = true) -> (head_dim, heads, n)

Causal grouped-query attention of the queries q (head_dim, heads, n) of one sequence, at the consecutive 0-based positions (a device vector of n Int32), over its first positions[end] + 1 cached positions. The sequence's keys and values are in the pages listed by block_table (a device vector, which may be padded past the sequence's pages). With causal = false, every query sees all positions[end] + 1 positions, including those of the later queries of the step (a DFlash drafter's block).

Sampling

TileInfer.sample_token! — Function
sample_token!(backend, ids, mirror, logits, sampler)

Sample a token from the logits (vocab, 1) with the parameters and seed of the TokenSampler sampler and its next counter, which it advances. The 0-based token goes to ids[1] and mirror[1], as sample_host picks it. On TileBackend this runs on the device and can be captured in a graph.

source
sample_token!(backend, ids, mirror, logits, sampler, (q_ids, q_probs))

sample_token! that also writes the distribution the token is sampled from, for speculative sampling (accept_token!): the 0-based ids of the filtered_dist survivors, best first, into q_ids (-1 past them) and their probabilities into q_probs (0 past them), vectors of MAX_TOP_K entries.

source
TileInfer.sample_tokens! — Function
sample_tokens!(backend, ids, mirror, logits, sampler, scratch, dists = nothing)

sample_token! on each column j of logits (vocab, n) in turn, into ids[j] and mirror[j] (and with dists, a pair of (MAX_TOP_K, n) matrices, column j's distribution into their column j), in a few launches on TileBackend. scratch is a zeroed sample_cols_scratch.

source
TileInfer.accept_token! — Function
accept_token!(backend, ids, mirror, logits, sampler, draft, (q_ids, q_probs))

The token a verify step emits at a position drafted as draft[1] from the distribution (q_ids, q_probs) (see accept_host): draft[1] with probability min(1, p/q) under the sampler's parameters, else a token from max(p - q, 0) that differs from it. Uses and advances the sampler's counter like sample_token!.

Quantization

TileInfer.Int8Weight — Type
Int8Weight

A linear weight (in, out) as Int8 values q with one Float32 scale per output column: W[:, j] ≈ scale[j] * q[:, j]. Made by quantize_int8.

source
TileInfer.quantize_int8 — Function
quantize_int8(W) -> Int8Weight

Round-to-nearest symmetric quantization of each column of W (in, out) to [-127, 127], with the scale max |W[:, j]| / 127 (1 for an all-zero column).

source
TileInfer.Int8Pages — Type
Int8Pages

A key or value page pool stored as Int8 values q (head_dim, page_size, kv_heads, num_pages) with one Float32 scale (page_size, kv_heads, num_pages) per cached vector: pool[:, o, h, p] ≈ scale[o, h, p] * q[:, o, h, p]. A layer's keys and values are the two halves of one Int8 array and one scale array (layer_q, layer_scale, keys first), so a kernel takes both pools as a single argument and stays under 32 parameters. Vectors are stored divided by smooth (head_dim), the keys' smoothing factors (ones for values): pool[:, o, h, p] ≈ smooth .* scale[o, h, p] .* q[:, o, h, p]. Made in pairs by int8_kv_pools.
