Internals

Everything that is documented but not public, grouped by source file. None of it is a stable interface: it is here because this project is meant to be read. The design behind it is in Architecture; measured kernel rules are in cuTile quirks.

TileInfer.StepBuffers — Type
StepBuffers(model, cache, n; all_logits = false, aux_layers = Int[])

Device memory for one forward step of n tokens: the step's inputs (token ids, positions, cache slots and a block table long enough for every page of the pool), every intermediate activation, and the logits of the last token, or of all tokens with all_logits. With aux_layers, the step also keeps the residual stream after each of those layers (1-based), stacked in aux, for a DFlash drafter (see DFlashProposer). A step that only writes into these buffers allocates nothing, so on a backend that supports_graphs it can be captured in a CUDA graph and replayed (see ModelRunner).

TileInfer.verify! — Method
verify!(runner, seq, ids, counter; dists = nothing, drafts = nothing) -> Vector{Int}

Run the 0-based token ids (the last sampled token, then the drafts) through the model, appending them to seq, and return the token the runner's sampler picks after each of them, with counters counter, counter + 1, … (the argmax when greedy). When the drafts were sampled from the distributions dists (column j for draft j), the token after each input but the last follows the p/q rule instead (accept_token!): the next draft if accepted, else a different token. Steps of each length, up to 16 tokens, are captured in a CUDA graph like forward! steps. With drafts, a device vector (see propose_on_device!), the drafts are read from it on the device rather than from ids[2:end], which then only hold places (and go into seq.tokens as they are).

cuTile kernels

One file per kernel family in src/ops/tile/. Each *_kernel function runs on the GPU; the launchers around it pick tile shapes and grids.

Normalization

TileInfer.add_rmsnorm_kernel — Method

Residual add + RMSNorm, one block per column: pass 1 sums the squares of x + delta, pass 2 recomputes it, stores it into x and the normalized value into H. Each tile is read in pass 2 before it is overwritten, and pass 1 never sees stored values.

source

Element-wise: RoPE, activations, KV writes, embedding

TileInfer.embed_kernel — Method

Embedding lookup, one block per token, walking the column in tiles.

source
TileInfer.expm1_tile — Method

expm1 without exp(x) - 1's cancellation (Kahan): with u = exp(x) rounded, (u - 1) x / log(u) is accurate to a few ulps, since u's rounding error cancels between the two factors. Below -20, expm1 is -1 in Float32 (and log(u) underflows further down).

source
TileInfer.rope_kernel — Method

Rotary embedding, one block per token over all heads. The two halves of head_dim are loaded as separate tiles (tile index 1 and 2 along the first axis), which is exactly the "rotate half" pairing: out1 = x1 cos1 - x2 sin1, out2 = x2 cos2 + x1 sin2. The cos/sin columns are looked up from the token's position, so positions can live on the device.

source
TileInfer.silu_mul_kernel — Method

SwiGLU: out = silu(gate) * up, with gate and up as separate (strided) views of the stacked gate_up activations. Grid: (tiles along intermediate, tokens).

source
TileInfer.store_int8! — Method

Quantize the vector whose two halves are the Float32 (HALF, 1) tiles x1 and x2 into column col of KV and its scale into S[col], as quantize_columns does.

source
TileInfer.store_kv_kernel — Method

KV-cache write, one block per token. Arrays are 2-D views, which keeps the launch under 32 kernel parameters: the pools as (head_dim, page_size × kv_heads × pages), whose column for (offset, head h, page), all 1-based, is offset + P (h - 1) + P H (page - 1), and k/v as (head_dim, kv_heads × n). Tile indices along the size-1 axis are element indices.

source
TileInfer.xielu_kernel — Method

xIELU, grid (tiles along the rows, tokens). The scalars are per layer and fixed, so launch arguments are fine inside a CUDA graph.

source
TileInfer.xielu_tile — Method

xIELU of a Float32 tile, rounding to T after each operation as the reference does.

Linear layers: GEMV and GEMM

TileInfer.gemm_int8_config — Function

INT8 GEMM tiles. The kernel converts each weight tile to T in registers, which BF16's tiles leave no room for (255 registers and spills at 128 × 128), and its loads of the Int8 tile are not overlapped like the BF16 operands', so its blocks are latency-bound: it wants two blocks per SM on every grid, narrower tiles at 512 tokens, and at ≤ 64 tokens (bandwidth-bound) deeper K steps that read as many bytes per step as BF16's. From a sweep of 15 tiles × occupancy 1, 2 on the layers of Qwen3-0.6B, Qwen3-4B and Apertus 8B at n = 8, 64, 512: within 1.5 % of the best tile in total (worst 1.11×), 1.23× the BF16 rule (down at 64 tokens: 2.1× on 4B, 1.7× on 8B).

source
TileInfer.gemm_occupancy — Function

Two GEMM blocks per SM when the grid has enough of them: the second hides the first's latency (4B gate_up at n = 512: 1.11×), but tileiras trims registers and shared memory to fit both, which slows grids that leave one block per SM (0.6B o/down at n = 512: 0.86×).

source
TileInfer.gemv_int8_config — Method

Int8 GEMV tiles of half the BF16 width: TK × TM ≈ 4096 elements was fastest on Apertus 8B's layers (TK = 1024, TM = 4: 600–670 GB/s; TM = 8 was 7–13 % slower).

source
TileInfer.gemv_int8_out — Method

Scaled, rounded GEMV outputs of column tile col, as Float32 (1, TM).

source
TileInfer.gemv_sums — Method

Float32 sums of TM weight columns against x, from column tile col: the GEMV loop.

source
TileInfer.gemv_swiglu_kernel — Method

GEMV with a SwiGLU epilogue for the stacked gate_up weight (in, 2I): block b reduces TM gate columns and the TM up columns I apart, and writes silu(gate) * up, rounding as silu_mul_kernel does after a plain GEMV. Needs I divisible by TM.

source
TileInfer.gemv_xielu_kernel — Method

GEMV with an xIELU epilogue (Apertus' up projection): the plain GEMV, then xielu_tile on the rounded sums, as xielu_kernel computes after it.

source

Paged flash-attention

TileInfer.attend — Method

An INT8 cache: the keys and values are converted to T for the tensor cores, the key's scale multiplies its row of scores (s_k q_kᵀ x) and the value's scale its probability (V diag(s_v) p). Converting whole (64, 128) pages of keys and values takes 255 registers and spills, so the kernels take 32 keys at a time, and K, V, the queries and the accumulator in two halves of the head dimension: q = (q1, q2), acc = (acc1, acc2).

source
TileInfer.attend — Method

One key tile of the online softmax for the query tile q (D, M) at positions qpos (1, M): its KEYS keys, at positions first_key + 1 : first_key + KEYS, are tile column kcol of K (width KEYS) and their values tile column vcol of V. S holds the scales of an INT8 cache (Int8Pages), at the same tile index as their vectors; it is nothing otherwise.

source
TileInfer.attention_combine_kernel — Method

Grid (GROUP n, kv_heads): merges the splits of one packed query column.

source
TileInfer.attention_decode_kernel — Method

Grid (kv_heads, SPLITS). Column c of the packed query tile is head (h - 1) GROUP + g of token t, with c = g + GROUP (t - 1); NT ≥ n is the padded token count (decode_tokens). The partial of split s goes to column (h - 1) SPLITS + s of the workspace: acc in rows 1:D, m in row D + 1 and l in row D + 2.

source
TileInfer.attention_prefill_kernel — Method

The kernels take the pools as K and V with S = nothing, or an INT8 layer as KV (keys, then values from VALUES key tiles on) with its scales S and the keys' smoothing C, which multiplies the queries (attend_operands).

source
TileInfer.decode_tokens — Method

Padded token count of the packed decode query tile: at least DECODE_MIN_ROWS rows.

source

Split-KV partials for decode attention of the queries q (head_dim, heads, n): for each packed query row, split and KV head, the unnormalized output (rows 1:head_dim), running max and running sum (rows head_dim + 1 and + 2).

source
TileInfer.key_tile — Method

source

TileInfer.survivors — Function

The survivors among the chunks' candidates Ids: their 1-based ids (best first, 0 past top_k), their probabilities under temperature and top-k, zeroed outside the top-p prefix, and the mask of survivors. With several columns of logits (sample_tokens!), Ids and Logits are the flat arrays and col the column: its candidates are entries (col - 1) N + 1 : col N of Ids, and its logits start at (col - 1) V + 1.
