TileInfer.jl

A single-GPU LLM inference engine in Julia, written to learn how inference engines work from the inside and to try tile-centric GPU programming with cuTile.jl. Every hot kernel (GEMV/GEMM, paged flash-attention, normalization, RoPE, sampling) is a cuTile kernel; everything around them (weight loading, tokenizer, paged KV cache, CUDA graphs, speculative decoding) is plain Julia.

Not production software

TileInfer serves one conversation on one GPU, supports a handful of model families, and is tuned on a single card (RTX 4080 SUPER). The code favours being easy to read and measure over breadth of features. Use vLLM, SGLang or llama.cpp to serve models.

What is inside

  • Models: Llama 3, Mistral, Qwen3 and Apertus checkpoints from the Hugging Face hub, in BFloat16, with optional weight-only INT8 and an INT8 KV cache.
  • Kernels: every op has a reference implementation (CUDA.jl broadcasts and cuBLAS), which is the ground truth in tests, and a cuTile implementation, both selected by a backend type (RefBackend, TileBackend).
  • Engine: a paged KV cache with prefix reuse across chat turns, decode steps captured as CUDA graphs, sampling on the device and a host that runs one step behind the GPU.
  • Speculative decoding: n-gram lookup, a draft model, or a DFlash block drafter, with exact verification for greedy and sampled decoding.
  • Tooling: a tileinfer command line, per-op and end-to-end benchmarks, and Nsight Compute profiling scripts.

On Qwen3-4B, decode runs at 79 tok/s (88 % of the memory-bandwidth roofline) and prefill at 12k tok/s (1,024-token prompt). Results by feature has the numbers for each feature, including the variants that did not pan out, and Comparison with vLLM the engine against vLLM with speculative decoding.
